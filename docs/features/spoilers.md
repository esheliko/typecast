# Spoiler line: a saved place is that title's spoiler line, everywhere

> Read before changing what any surface tells about a series. Pure rules: `src/lib/spoiler-line.ts` (unit tested in `tests/unit/spoiler-line.test.ts`). Server lookup: `src/lib/spoiler-line-data.ts`. Gate: `src/components/SpoilerGate.tsx`.

**The rule.** A series that is **Watching** in the library has a spoiler line, whatever page or popup is showing it:
- **Watching with a saved place** (`progress_season/progress_episode`, "watched up to and including"): `{ kind: "upto", s, e }`. Episodes up to and including that place may be told. The episode after it (the one being watched now) and everything later stays hidden until Show.
- **Watching with no saved place**: `{ kind: "series-only" }`. Series-level facts only: no episode names, plots, later seasons, dates that give the run away, or character descriptions. The gate adds a dismissible hint (localStorage `typecast.placeHint.<key>`, try/catch) to set the place.
- Everything else keeps today's behaviour (`{ kind: "none" }`): Watchlist, Watched, Partly watched, not in the library, and every film (a film has no place).
- Show is **one view, one request** (`reveal=1`; Glimpse's older `full=1` means the same). It is never remembered, never writes to the library and never moves the saved place.
- The /watching page-wide **No spoilers** switch lifts the line only for the title being watched on that page. The client sends `pg=<page title key>` (and `ps=1` when its spoilers are shown); the page's own title is governed by the page (its position, `clip`, the switch) and has no library line; every OTHER Watching title stays protected even with spoilers shown. `scopeSpec` no longer returns early when spoilers are shown: it always adds `pg`/`ps`.

**Where it is enforced (server, so held-back data never reaches the browser).** Each route reads the title's row through `lineFor` / `lineForMany` (the one cached `getLibrary()` read per request; if the library cannot be read the answer is `none`, today's behaviour). Params: `pg`, `ps`, `reveal` (`lineContextFrom`).
- `/api/season` (`holdBackSeason`): episodes after the line keep S/E, air date and runtime only, marked `hidden: true` (no name, plot, still, crew, guests, rating, finale flag); the response carries `hidden: { kind, s?, e? }`.
- `/api/episode`: an episode after the line answers `{ hidden }` with no cast.
- `/api/appearances` (`holdBackAppearances`): later episodes and seasons are **dropped, not listed** (that an actor turns up in a later episode is itself the spoiler); "every episode (62)" counts go; `hidden` set.
- `/api/who/spans` (`spanUnderLine`, `loadSpans`): per-key lines from the library for every series asked for except the watched one; dates stop at the saved place, no `show` run (end date, still airing) is ever sent for a held-back series, a series with no place does no TMDB lookup at all and returns an empty stub with `hidden`. `reveal=1` or `reveal=tv:1,tv:2` lifts keys for that request.
- `/api/who/title` (`holdBackBrief`): no end date, status or later seasons, and a `hidden` marker.
- `/api/glimpse/info`: `aboutRole` clips the actor's episode list and season rows to the line (`clipEpisodes`, `clipSeasonList`), with no place nothing at all and no character note (not even the careful sentence); role `hidden` marker; the "Show the full description anyway" button is not drawn for a held-back title (the gate's Show does the same refetch).

**Client.** `SpoilerGate` (`Spoilers hidden for <Title> · Show · Set my place`, `compact` for rows) is used only where a route returned `hidden`: Glimpse About, `Appearances`, the season list and opened episodes in `Episodes`, the /watching person timeline rows (`TRow`) and the title node (`TitleNode`, its cast rows). Show flips a per-view state and refetches with `reveal`. Set my place goes to `/watching?k=<key>` (the pickers save the place while the title is Watching). The gate's CSS is `.sgate*` (no `wx-` class).

**The browser knows the saved place (step 4B-1).** `Mark.progress` carries it for a Watching series (`packMark` adds `<s>.<e>` after the four characters; an old 4-character string still unpacks with no place). `app/(app)/layout.tsx` fills it from `getLibrary()` (nothing there awaits TMDB). `LibProvider.setPlace(key, place, status?)` moves it on screen only, with NO server write (a quick mark is one write): it is called by `Episodes` (`moveTo`) and `useSavedPlace` (`flush`, `restore`/Undo, `next`) **after** their own write resolved, never before, so a request made under the new key cannot reach the server first. `save()`/`mark()` carry `prev.progress` through a status flip and the override-clearing effect compares the place too (`sameMark`). The browser reaches the server's line with the same pure rule: `markLine(key, mark, ctx)` (`spoiler-line.ts`).

**Caching: exact keys, no short TTLs.** Every client cache keys on the line the server will use: `lineTag` (`.` none, `s` series-only, `u2.8` up to S2 E8) inside `lineCacheKey({ page, reveal, line })`, so a moved place, another page, switch or Show is simply another entry. `who-client.ts` `getJson(url, ttl, tag)` (`cacheKey`; `LINE_TTL_MS` is gone) for `/api/who/spans` (`lineTags` of the keys asked; `useSpans` also asks a row again when its line moves) and `/api/who/title`; `Appearances`, `Episodes` (season and episode-cast answers) key the same way; Glimpse's About query carries `lt` (`withLine`, `infoQuery`), a cache discriminator only (the server ignores it). The routes still answer `Cache-Control: private, max-age=0`. The only TTL left is Glimpse About's 60 s: marking a title Watched changes what the server tells and nothing in the key sees that.

**The page context for popups.** A title popup opened over /watching renders in the (app) layout's `@modal` slot, outside `WhoApp`. `WhoApp` publishes `{ key, spoilersShown }` (`usePublishPageLine`, `components/PageLine.tsx`; the provider sits in the layout above both the page and the modal slot; cleared when the page unmounts). `Episodes`, `Appearances` and Glimpse (`GlimpseLineFeed` hands the provider the marks and the page, because the Glimpse provider sits above `LibProvider`) read it and send `pg`/`ps` through `pageFor(page, key)`: only while the switch SHOWS spoilers and only for the page's own title. With No spoilers ON nothing is sent, so the popup keeps the library line (protective). A spec that already names the page (`scopeSpec`) keeps it.

**Step 4B-2 (done): person and credit masking.** Pure rules in `src/lib/spoiler-mask.ts` (unit tested, `tests/unit/spoiler-mask.test.ts`).
- "Seen in" (Finder tile, `pickSeenIn`) does not count a Watching series as seen (`seenMark`); Watched, Partly and films work as before. The same holds in the title popup's "You know them from" (`enrich.ts`): a Watching series is named only when `seenIn` shows they have appeared by the saved place, never on part size alone.
- The person node's "You know them from" draws the compact `SpoilerGate` row (no role, dates or episode count) for a Watching series; Show lifts that row, this view only.
- `/api/who/person` reads the library (`lineForMany`, `pg`/`ps`/`reveal` like /api/who/spans): a held-back series' credit has `eps: 0`, no `cids` and a `hidden` marker (`holdBackCredits`); other credits are the same objects. `private, max-age=0`.
- Credit counts: a cast member's other credits (`enrich` -> `TopCredits`) and `PersonView` rows lose `eps`/`since`/`cids` for a Watching series (`maskCreditItem`, role stays); the cast rows of a Watching series' own title show no "N eps" / "every episode" (`hold` prop from `TitleView`). Season tabs are kept (series length is a series-level fact). `/api/season-cast` ("Cast by season") and the Focus line of a person-opened title also drop per-person counts (`holdBackCast`, `hold`). The gated "You know them from" row shows no Seen chip.

**Not done yet.** `/api/who/known` still ships `eps` for every credit (used for ranking only; the tile never shows it) and a credit's first-air `date` stays in `/api/who/person`. `/api/who/person` callers do not send `pg` yet, so the page's own title is held back there too (the page does not need its credit's counts). Title `overview` and `/api/who/season` (watched title only) were not changed.
