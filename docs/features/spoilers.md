# Spoiler line: a saved place is that title's spoiler line, everywhere

> Read before changing what any surface tells about a series. Pure rules: `src/lib/spoiler-line.ts` (unit tested in `tests/unit/spoiler-line.test.ts`). Server lookup: `src/lib/spoiler-line-data.ts`. Gate: `src/components/SpoilerGate.tsx`.

**The rule.** A series that is **Watching** in the library has a spoiler line, whatever page or popup is showing it:
- **Watching with a saved place** (`progress_season/progress_episode`, "watched up to and including"): `{ kind: "upto", s, e }`. Episodes up to and including that place may be told. The episode after it (the one being watched now) and everything later stays hidden until Show.
- **Watching with no saved place**: `{ kind: "series-only" }`. Series-level facts only: no episode names, plots, later seasons, dates that give the run away, or character descriptions. The gate adds a dismissible hint (localStorage `typecast.placeHint.<key>`, try/catch) to set the place.
- Everything else keeps today's behaviour (`{ kind: "none" }`): Watchlist, Watched, Partly watched, not in the library, and every film (a film has no place).
- Show is **one view, one request** (`reveal=1`; Glimpse's older `full=1` means the same). It is never remembered, never writes to the library and never moves the saved place.
- The /watching page-wide **No spoilers** switch lifts the line only for the title being watched on that page. The client sends `pg=<page title key>` (and `ps=1` when its spoilers are shown); the page's own title is governed by the page (its position, `clip`, the switch) and has no library line; every OTHER Watching title stays protected even with spoilers shown. `scopeSpec` no longer returns early when spoilers are shown: it always adds `pg`/`ps`.

**Where it is enforced (server, so held-back data never reaches the browser).** Each route reads the title's row through `lineFor` / `lineForMany` (the one cached `getLibrary()` read per request; if the library cannot be read the answer is `none`, today's behaviour). Params: `pg`, `ps`, `reveal` (`lineContextFrom`).
- `/api/season` (`holdBackSeason`): episodes after the line keep S/E, air date and runtime only, marked `hidden: true` (no name, plot, still, crew, guests, rating, finale flag); the response carries `hidden: { kind, s?, e? }`.
- `/api/episode`: an episode after the line answers `{ hidden }` with no cast.
- `/api/appearances` (`holdBackAppearances`): later episodes and seasons are **dropped, not listed** (that an actor turns up in a later episode is itself the spoiler); "every episode (62)" counts go; `hidden` set.
- `/api/who/spans` (`spanUnderLine`, `loadSpans`): per-key lines from the library for every series asked for except the watched one; dates stop at the saved place, no `show` run (end date, still airing) is ever sent for a held-back series, a series with no place does no TMDB lookup at all and returns an empty stub with `hidden`. `reveal=1` or `reveal=tv:1,tv:2` lifts keys for that request.
- `/api/who/title` (`holdBackBrief`): no end date, status or later seasons, and a `hidden` marker.
- `/api/glimpse/info`: `aboutRole` clips the actor's episode list and season rows to the line (`clipEpisodes`, `clipSeasonList`), with no place nothing at all and no character note (not even the careful sentence); role `hidden` marker; the "Show the full description anyway" button is not drawn for a held-back title (the gate's Show does the same refetch).

**Client.** `SpoilerGate` (`Spoilers hidden for <Title> · Show · Set my place`, `compact` for rows) is used only where a route returned `hidden`: Glimpse About, `Appearances`, the season list and opened episodes in `Episodes`, the /watching person timeline rows (`TRow`) and the title node (`TitleNode`, its cast rows). Show flips a per-view state and refetches with `reveal`. Set my place goes to `/watching?k=<key>` (the pickers save the place while the title is Watching). The gate's CSS is `.sgate*` (no `wx-` class).

**Caching.** The routes above answer with `Cache-Control: private, max-age=0` (`okWho(..., 0)` on the /api/who ones). The browser does not know the saved place (it is not in `Mark`), so its caches cannot key on the line: `who-client.ts` keeps `/api/who/spans` and `/api/who/title` answers 30 s (`LINE_TTL_MS`, `fresh`), Glimpse's About cache keeps a held-back answer 15 s (a normal one 60 s), `Appearances` keeps a held-back answer 15 s, and `Episodes` keys its season answers by the saved place it has seen saved (`placeKey`, updated only after `setWatchedUpTo` resolves) and by Show. `pg`, `ps` and `reveal` are part of every request URL, so another page, switch state or Show is another cache entry (`lineCacheKey`, `lineParams`).

**Not done yet (step 4B).** The client-side masking that needs `Mark.progress`: the finder tile's and the person node's "Seen in / You know them from" still count a Watching series as seen with no check against the place (`pickSeenIn`); the title popup's season tabs and its counts, `CreditRow` episode counts and `PersonView` credit counts; `/api/who/person` still sends every credit's total episode count (the person node hides it for held-back rows). Also not done: the title `overview` and `/api/who/season` (watched title only).
