# Marks and freshness

> Moved verbatim out of CLAUDE.md so sessions only read it when they touch this feature.

- Marks and freshness: a quick mark (episode ticks and "Tick whole season" via `setWatchedUpTo` included, poster eye/bookmark/check, popup status chips, rating, episode progress) is ONE database write and nothing else. `setStatus`/`setPriority`/`setRating`/`setProgress` do NOT call `revalidatePath` (that re-rendered the layout, re-read the whole library, ran the new-episode check and re-rendered the open page on every tap). `LibProvider` is the truth on screen: its overrides update every poster and the popup at once (`StatusControls` saves through `useLib().put`, so the poster underneath changes too; call `useLib().touch()` after any other quick save). Server-rendered data (Library, Watch next, Continue watching, stats) is brought up to date by ONE `router.refresh()` on the first page change after a burst of marks, once the queued saves have landed (opening a popup does not count; closing it back to the page does). Bulk and settings actions (`setStatusMany`, import, rollback, Letterboxd, profile) and `setStatusFresh` (import review) still call `done()` for a full refresh. Never add `done()` to a quick-mark action. `RecheckOnce` runs the new-episode and Letterboxd check once per browser session (30 min, `sessionStorage`) via `POST /api/recheck` (a route, not an action: actions run one at a time per client and would block marks), and refreshes only if something moved.
- Film resume rides on the same rule: the film's stopped time is one debounced write from the film clock (`setStopped`), shown on screen through `useLib().setStopped` / `Mark.stopped` with no revalidation (`docs/features/film-resume.md`).
