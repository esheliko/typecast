# Glimpse (the profile-card button)

The button beside every title, cast row and credit opens one panel: **About** (words) on top, **Images** below. Icon: a framed face with lines of text and a spark (`GlimpseButton` in `components/Glimpse.tsx`); it is no longer a photo stack because the panel is more than pictures.

**What About shows** (server: `lib/glimpse-data.ts` `loadAbout`, route `/api/glimpse/info`; pure text work in `lib/glimpse-info.ts`, unit tested)
- **Character note sources:** the title's Wikipedia cast list first (`characterBlurb`; then the separate "List of <title> characters" article), then the show's **Fandom wiki** (`lib/fandom.ts`: the wiki comes from Wikidata's Fandom ID (P6262) by IMDb id, else guesses (joined, hyphenated, initials like "himym"); every candidate, Wikidata's too (it can list several, in other languages, or unrelated), is accepted only when the wiki's own name is the title (`siteNameMatches`; a wiki Wikidata itself lists may also be "<title>pedia", e.g. Lostpedia); MediaWiki API search then the page's intro; `fandomNote`, `pickFandomPage`). Both are linked as the source (Fandom is CC-BY-SA). Fandom text is read with `action=parse` (section 0, `introFromHtml`), NOT `prop=extracts`: the Blade Runner and HIMYM wikis have no TextExtracts extension, so extracts silently returned nothing. Checked live (Blade Runner: "Sushi Master" and "Howie Lee" -> "Howey Lee" by `near` spelling; HIMYM "Ted Mosby"); a one-episode role with no wiki page (HIMYM "Samantha") correctly finds nothing. In the sandbox node `fetch` ignores the proxy: test live lookups through curl.
- Actor + title (cast row on a title, a credit on a person's page, a person opened from a title, a Watching-now timeline row): the **character** (a short note from the title's Wikipedia cast list, `characterBlurb`; no AI), **which episodes** they were in and **when** (series: `getAppearances` from TMDB `/credit/{id}`; a regular is listed by season with air dates), and the images of them in the role. The credit ids come from the person's TMDB credits on the server, so callers pass only ids (`pid`, title `key`).
- Title only: its summary (TMDB overview) and a facts line. Person only: life line and a short biography.
- No character note found (Wikipedia blocked/slow, or the cast list is on another article): the panel says so (no title summary is added: a character's panel is about the character). Small parts: Wikipedia lists them under another name ("Robert Okazaki as Howie Lee" for TMDB's "Bob Okazaki as Sushi Master"); `minorRole` finds that clause by the actor's surname, its role name is tried on the Fandom wiki too, and the bare clause is shown only if Fandom has nothing. Order: Wikipedia cast paragraph, Fandom (character, then that alias), bare cast clause. A slow Wikipedia answer is skipped after 5 s (it is cached for next time).

**Specs** (`lib/glimpse.ts`): `GlimpseSpec.info` = `{key, pid, char, clip, nospoil, hide}`; no ids means images only. Builders take the ids: `titleSpec` (title `key` or `id`), `personSpec(name, dept, pid)`, `castSpec(..., pid)`, `creditSpec(actor, role, title, pid)`, `personInTitleSpec(..., pid)`. Add the ids when you add a new button.

**Spoilers.** The server decides from the library: a title marked **Watched** is told in full (3-sentence note, every episode, counts), whatever the position or the No spoilers switch (that switch only applies to what is being watched now). Any other title, on any page, is told conservatively (`RISKY` words in `glimpse-info.ts`: one sentence with no deaths, twists, seasons or endings; no season counts). The client cache keeps an answer a minute, the API is not cached. Below, the Watching-now details.

**Spoilers (Watching now).** Wrap the spec in `scopeSpec(spec, {key, title, clip, spoilers})` (`PersonNode` does). With No spoilers on: the character note is one sentence, biographies drop sentences naming the watched show or talking about seasons/episodes, title facts drop season counts and "ended". For the watched show itself the episode list, season list and counts stop at the position (`clip`, via `inScope`); seasons-only rows say "Episodes 1-8" for the current season. Spoilers allowed or outside /watching: everything. The image searches are not filtered.

**Show it anyway.** When the server held something back (`limited` in the About answer: a fuller character note exists but the title is not marked Watched, or a biography was trimmed by No spoilers; no button when nothing was found), the panel shows "Show the full description anyway (may contain spoilers)". It refetches with `full=1`, which the route treats like Watched with no clip and no No spoilers. The choice is per panel and is not remembered.

**Watching-now cast faces.** Every face tile in the Finder (`Tile` in `components/who/Finder.tsx`) has the Glimpse button on the photo's top-right corner (`.wx-tileg`, a sibling of the tile button, never inside it). It opens the character of the watched title (`castSpec` + `scopeSpec`, so the position and No spoilers switch apply) without opening the person first.

**"Then" photos (Watching now finder).** For a title 8+ years old (`isOldTitle`, `lib/then-photo.ts`, unit tested) the chips row offers Photos: Now | Then (off by default, remembered in `typecast.who.then`). On, each face on screen swaps its profile photo for the first image of the Glimpse "In the role" search (same query as the panel's first tab, so it shares the 30-day server cache; 3 at a time, at most 24 per pass) in the same 2:3 box with a small year badge, so nothing moves. No image or a load error keeps the profile photo; with image search not configured the switch is hidden. TMDB cannot do this: `/person/{id}/tagged_images` holds only a few posters, no stills.

**Then-photo loading (Finder).** The lookups run from a queue held in refs (`thenQueue`, 3 at a time), not from the effect itself: an effect that owned the loop dropped the faces still waiting whenever the grid re-measured, so only the first few faces ever got a Then photo. A failed lookup is retried twice (0.7 s, 1.4 s) and, if it still fails, asked again on the next change of the visible faces.

**Then is never the Now photo.** `pickThen` (`lib/then-pick.ts`, used by the Finder queue and `PersonNode`) takes the first role-search image that is not the profile photo: skipped when it has the same address/file name (`sameImageUrl`) or, if both images can be read on a canvas (CORS), a 9x8 difference hash within `SAME_PHOTO_BITS` (`pickThenUrl`, unit tested). If every candidate is a duplicate there is no Then photo and the profile photo stays. Unreadable pixels fall back to the address check only.

**Fixed height, prefetch.** `.gl` has a fixed `height: 88dvh` (not max-height), so the panel never resizes while answers arrive. Everything is fetched ahead and kept in module caches in `Glimpse.tsx` (`loadImages` + `imgDone`, `loadAbout` + `peekAbout`, `loadRoles`): `GlimpseButton` prefetches the words and library roles once it has been on screen 600 ms, and everything (all tabs' image searches, thumbnails preloaded) on pointer-enter / focus / touchstart; opening the panel fetches all tabs at once, not just the visible one. A result already in the cache renders on the first paint (no "Finding images" / "Reading up" flash). Failed image answers are not cached.

**Library-role tabs (Watching-now cast).** Specs built for the cast of the watched title go through `withLibRoles(spec, actor)` (Finder tile, TitleNode cast row, PersonNode "here" line). The panel then asks `/api/glimpse/roles?p=<pid>&k=<title>` (server: the actor's TMDB credits filtered to titles in the user's library, not the current one, no talk-show/"Self" credits, at most 6: `libraryRoles`, unit tested) and adds one tab per role after the first: label `Character · Title`, images of the actor as that character, and the About text follows the tab (`GlimpseTab.info`; spoiler rules: other titles are told conservatively unless marked Watched). The first tab is now named after the character ("Nell"), no longer "In the role". Tabs are selected by query, not index, because role tabs arrive after opening.
