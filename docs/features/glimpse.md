# Glimpse (the profile-card button)

The button beside every title, cast row and credit opens one panel: **About** (words) on top, **Images** below. Icon: a framed face with lines of text and a spark (`GlimpseButton` in `components/Glimpse.tsx`); it is no longer a photo stack because the panel is more than pictures.

**What About shows** (server: `lib/glimpse-data.ts` `loadAbout`, route `/api/glimpse/info`; pure text work in `lib/glimpse-info.ts`, unit tested)
- **Character note sources:** the title's Wikipedia cast list first (`characterBlurb`; then the separate "List of <title> characters" article), then the show's **Fandom wiki** (`lib/fandom.ts`: the wiki comes from Wikidata's Fandom ID (P6262) by IMDb id, else guesses (joined, hyphenated, initials like "himym"); every candidate, Wikidata's too (it can list several, in other languages, or unrelated), is accepted only when the wiki's own name is the title (`siteNameMatches`; a wiki Wikidata itself lists may also be "<title>pedia", e.g. Lostpedia); MediaWiki API search then the page's intro; `fandomNote`, `pickFandomPage`). Both are linked as the source (Fandom is CC-BY-SA). Fandom was written against the documented API only: the dev sandbox blocks it, so check a real show after changes.
- Actor + title (cast row on a title, a credit on a person's page, a person opened from a title, a Watching-now timeline row): the **character** (a short note from the title's Wikipedia cast list, `characterBlurb`; no AI), **which episodes** they were in and **when** (series: `getAppearances` from TMDB `/credit/{id}`; a regular is listed by season with air dates), and the images of them in the role. The credit ids come from the person's TMDB credits on the server, so callers pass only ids (`pid`, title `key`).
- Title only: its summary (TMDB overview) and a facts line. Person only: life line and a short biography.
- No character note found (Wikipedia blocked/slow, or the cast list is on another article): the panel says so (no title summary is added: a character's panel is about the character). Small parts are matched by the actor's surname in the cast line (`minorRole`: "Robert Okazaki as Howie Lee"). A slow Wikipedia answer is skipped after 5 s (it is cached for next time).

**Specs** (`lib/glimpse.ts`): `GlimpseSpec.info` = `{key, pid, char, clip, nospoil, hide}`; no ids means images only. Builders take the ids: `titleSpec` (title `key` or `id`), `personSpec(name, dept, pid)`, `castSpec(..., pid)`, `creditSpec(actor, role, title, pid)`, `personInTitleSpec(..., pid)`. Add the ids when you add a new button.

**Spoilers.** The server decides from the library: a title marked **Watched** is told in full (3-sentence note, every episode, counts), whatever the position or the No spoilers switch (that switch only applies to what is being watched now). Any other title, on any page, is told conservatively (`RISKY` words in `glimpse-info.ts`: one sentence with no deaths, twists, seasons or endings; no season counts). The client cache keeps an answer a minute, the API is not cached. Below, the Watching-now details.

**Spoilers (Watching now).** Wrap the spec in `scopeSpec(spec, {key, title, clip, spoilers})` (`PersonNode` does). With No spoilers on: the character note is one sentence, biographies drop sentences naming the watched show or talking about seasons/episodes, title facts drop season counts and "ended". For the watched show itself the episode list, season list and counts stop at the position (`clip`, via `inScope`); seasons-only rows say "Episodes 1-8" for the current season. Spoilers allowed or outside /watching: everything. The image searches are not filtered.

**Show it anyway.** When the server held something back (`limited` in the About answer: a fuller character note exists but the title is not marked Watched, or a biography was trimmed by No spoilers; no button when nothing was found), the panel shows "Show the full description anyway (may contain spoilers)". It refetches with `full=1`, which the route treats like Watched with no clip and no No spoilers. The choice is per panel and is not remembered.

**Watching-now cast faces.** Every face tile in the Finder (`Tile` in `components/who/Finder.tsx`) has the Glimpse button on the photo's top-right corner (`.wx-tileg`, a sibling of the tile button, never inside it). It opens the character of the watched title (`castSpec` + `scopeSpec`, so the position and No spoilers switch apply) without opening the person first.

**"Then" photos (Watching now finder).** For a title 8+ years old (`isOldTitle`, `lib/then-photo.ts`, unit tested) the chips row offers Photos: Now | Then (off by default, remembered in `typecast.who.then`). On, each face on screen swaps its profile photo for the first image of the Glimpse "In the role" search (same query as the panel's first tab, so it shares the 30-day server cache; 3 at a time, at most 24 per pass) in the same 2:3 box with a small year badge, so nothing moves. No image or a load error keeps the profile photo; with image search not configured the switch is hidden. TMDB cannot do this: `/person/{id}/tagged_images` holds only a few posters, no stills.
